# 过流采样优化 — 实施清单

> 目标文件：`USER/main.c`、`USER/system/sys_main_state.c`、`USER/system/system.c`、`USER/system/motor_cmd.h`、`USER/system/motor_adc.c`、`USER/system/motor_adc.h`、`USER/adapter/adc_adapter.c`（仅参考）
> 状态：2026-08-22 复核并确认决策：**取消 ADC2 方案**，电流检测留在 ADC1；已启用的电流/电压两通道统一由 50µs 中断采样（方案 A：电流每 tick、电压隔 tick；温度/电位/mc_cur 不启用），详见第 9 节。
> 本清单只列改动点与设计约定，不包含完整代码；实施时按此清单逐项落实。

---

## 0. 背景与目标

- 现状问题：过流检测（采样→比较→判定→停机）全部在主循环轮询。1ms 定时器只负责计数，采样节奏 = 主循环节奏，导致“20 点一批”实际耗时约 240ms 而非 20ms。
- 优化目标：用 **50µs ADC 中断采样 + 10ms 滚动窗口 + 30% 占比判定 + 1ms 门控**，把过流响应变成确定、可预期的时间。
- 硬性约束（决策 5）：**过流之后的处理完全不动**（软限位语义、停机时机、`Time_Current_Over` 累计、不进 `SYS_STATE_FAULT` 等）。

---

## 1. 定稿参数（宏，全部放 `USER/system/motor_adc.h`）

| 宏 | 取值 | 含义 |
|---|---|---|
| `ADC_CUR_SAMPLE_INTERVAL_US` | `50` | 电流采样间隔 50us = 20kHz |
| `OC_WINDOW_MS` | `10` | 判定窗口 10ms（直接由窗口算，不写 60-50） |
| `OC_WINDOW_SAMPLES` | `(OC_WINDOW_MS * 1000u) / ADC_CUR_SAMPLE_INTERVAL_US` = **200** | 环形缓冲长度 |
| `OC_TRIP_PERCENT` | `30.0f` | 窗口内超阈值点数占比触发值（%） |
| `OC_TRIP_SAMPLES` | `(uint16_t)(OC_WINDOW_SAMPLES * OC_TRIP_PERCENT / 100.0f)` = **60** | 整数阈值（校验用） |
| `THRESHOLD_CURRENT_OVER` | `1.50f` | 过流阈值（不变） |
| `TIME_SAMPLE_CURRENT_OVER` | `1` | 变死参数，暂留不动 |

> 注意：**不要复用 `SampleTime_cur`（现在是“采样点数=20”，语义与 ms 无关）**，窗口用新宏 `OC_WINDOW_MS` 表达，避免破坏 `adc_adapter.c` 里的 `SampledTime >= SampleTime` 判断。

## 2. 架构与数据流

```
电机启动
  └─ 消隐 50ms：不判过流（现状保留：MOTOR_PROTECT 整体跳过）
        │  （50ms > 10ms 窗口，消隐结束时缓冲内已全是启动后数据）
        ▼
  ┌─────────────── 50us ADC 中断（新）───────────────┐
  │ 读 ADC 原始码 → 写环形缓冲(覆盖) → 整数比较      │
  │ → 维护窗口内超阈值点数 s_oc_above_count          │
  └───────────────────────────────────────────────────┘
        │
  ┌─────────────── 1ms 定时中断（system.c，改）──────┐
  │ 只置门控 s_oc_gate = true（不比较、不浮点）      │
  └───────────────────────────────────────────────────┘
        │
  ┌─────────────── 主循环（sys_main_state.c，微改）──┐
  │ 消费门控 → 浮点算占比 → 判过流 → 走现有处理     │
  └───────────────────────────────────────────────────┘
```

- 采样、计数：50us 中断，全部整数操作；
- 门控：1ms 中断，只置标志；
- 判定：主循环消费门控后做浮点占比运算（浮点只在主循环）。
- （2026-08-22 更新：按用户决策不再使用 ADC2；50µs 中断采用方案 A，电流每 50µs 必采、电压隔 tick 采样，仅此两通道启用，详见 9.3/9.4。）

3. 保留现有宏与接口（`THRESHOLD_CURRENT_OVER`、`ADC_CUR_ARRAY_COMPARE` 等暂不动）。

### 3.2 `USER/system/motor_adc.c`

1. 新增静态变量：
```c
static uint16_t s_oc_ring[OC_WINDOW_SAMPLES];   /* 原始 ADC 码环形缓冲, 200×uint16 = 400B */
static uint16_t s_oc_head = 0;                   /* 写指针 */
static uint16_t s_oc_above_count = 0;            /* 窗口内超阈值点数 */
static volatile bool s_oc_gate = false;          /* 1ms 门控 */
static bool s_oc_trip = false;                   /* 过流判定结果 */
static uint16_t s_oc_thr_hi = 0;                 /* 上阈值 ADC 码 */
static uint16_t s_oc_thr_lo = 0;                 /* 下阈值 ADC 码 */
```

2. 阈值换算（在校准完成后、主循环里算一次并存入 `s_oc_thr_hi/lo`）：
- 电流公式：`Current = (mV - 1650) / 264 + offset`
- 上阈值：`mV_hi = 1650 + 264 * (1.5 - offset)`
- 下阈值：`mV_lo = 1650 - 264 * (1.5 + offset)`
- ADC 码：`code = mV / 3.3 * 4096`（12 位，参考 `adc_adapter.h` 的 `ADC_REF_VOLTAGE=3.3f / ADC_FULL_SCALE=4096`）
- 超阈值判定（整数，无浮点）：`raw > s_oc_thr_hi || raw < s_oc_thr_lo`

3. `OC_50us_ISR()` 伪代码：
```c
void OC_50us_ISR(void)
{
    uint16_t raw = <读 ADC1 转换结果>;      /* 12bit 原始码 */
    uint16_t old = s_oc_ring[s_oc_head];    /* 被覆盖的旧点 */

    s_oc_ring[s_oc_head] = raw;
    s_oc_head = (s_oc_head + 1) % OC_WINDOW_SAMPLES;

    if (raw > s_oc_thr_hi || raw < s_oc_thr_lo) s_oc_above_count++;
    if (old > s_oc_thr_hi || old < s_oc_thr_lo) s_oc_above_count--;
}
```

4. 门控与判定：
```c
void OC_Gate_Tick(void) { s_oc_gate = true; }                 /* 1ms ISR 调用 */

/* 主循环调用：消费门控并更新判定（可放 MotorProtect_Generate 内部） */
static void OC_Process(void)
{
    if (!OC_Gate_Pending()) return;
    OC_Gate_Clear();

    if (<处于消隐期>) return;                 /* 消隐期消费门控但不判定 */

    float percent = (float)s_oc_above_count * 100.0f / (float)OC_WINDOW_SAMPLES;
    s_oc_trip = (percent >= OC_TRIP_PERCENT);
}
```

5. 改造 `MotorProtect_Generate`（motor_adc.c:76）：
- 在函数开头调用一次 `OC_Process()`（内部由门控节流，1ms 才真正判定一次）；
- 把 `MOTOR_STOP` 分支（97-109 行）和 `MOTOR_RUN_*` 分支（173-181 行）里的过流判断，从“轮询 `ADC_CUR_ARRAY_COMPARE` 结果 + `time_sample_current_over` 计数”改为读 `OC_Get_TripFlag()`：
  - 判过流：`s_motor_current_over = true; time_sample_current_over++; err = ERROR_OVER_CURRENT;`
  - 未过流：`s_motor_current_over = false; time_sample_current_over = 0;`
- 保留过压/欠压检测顺序与逻辑不动；
- `s_motor_current` 的刷新可改为从环形缓冲取平均（主循环浮点）或保持原逻辑，二选一。

6. 校准衔接（注意点）：
- 现有 `ADC_CURRENT_Calibration_Process()`（motor_adc.c:429）仍走 `hz_adc_adapter_SCM_1Ch_Convert_CUR` 轮询采样；
- 新方案下建议：校准完成后在主循环用新换算公式更新 `s_oc_thr_hi/lo`；
- 不要在校准期间混用两套采样机制（50us 中断与新路径启动时机错开）。

### 3.6 ADC 触发与中断配置（硬件层）

1. 50us 触发方式（二选一，按工程定时器资源确认）：
   - **方案 A（推荐）**：选一个可用定时器（如 TIM4/TIMA）产生 50us 周期，硬件触发 ADC1 转换；ADC1 转换完成产生 EOC 中断，在 EOC 中断服务里调用 `OC_50us_ISR()`。
   - **方案 B**：50us 定时器中断里软件启动 ADC1 转换，EOC 中断读结果后调用 `OC_50us_ISR()`。
2. 中断优先级：**ADC EOC 中断优先级高于 1ms 门控中断**，避免采样丢失。
3. ISR 内只做整数操作（读结果、入缓冲、计数），不做浮点、不打印、不调 `ring_buffer_put`。
4. ADC1 共享提醒：电流 IN5 / 电压 IN6 在 ADC1（温度 IN7 / 电位 IN4 本工程不启用）。电流 20kHz 每 tick 采样、电压隔 tick 采样（方案 A）；50µs ISR 独占 ADC1，主循环不再轮询，无饿死问题，见 9.3/9.4。

## 4. 判定逻辑（主循环，浮点只在主循环）

```c
/* MotorProtect_Generate 内部，每轮主循环调用，由门控节流到 1ms 一次 */
if (OC_Gate_Pending()) {
    OC_Gate_Clear();
    if (在消隐期) { /* 不判定 */ }
    else {
        percent = OC_Get_AboveCount() * 100.0f / OC_WINDOW_SAMPLES;
        oc_flag = (percent >= OC_TRIP_PERCENT);   /* 30.0f */
    }
}
/* oc_flag → 现有处理：s_motor_current_over / err = ERROR_OVER_CURRENT */
```

**响应延迟预算**（硬堵转从 0 开始）：
- 窗口内累计 60 个超阈值点 ≈ 60 × 50us = **3ms**；
- + 最多 1ms 等下一个门控；
- + 最多一个主循环周期（主循环消费门控的延迟）；
- + 现有传播一拍（下一轮 `MotorCmd_Execute` 才 `Stop()`，决策 5 保持）。
- 从启动算再加 50ms 消隐。

## 5. 保持不动的部分（决策 5）

- 过流后的软限位处理：`current_limit_state` 置位、下一轮 `MotorCmd_Execute` 才 `Stop()`、不进 `SYS_STATE_FAULT`、`Time_Current_Over` 累计。
- 欠压/过压检测的顺序与逻辑。
- `TIME_SAMPLE_CURRENT_OVER` 死参数暂留，不删。
- 消隐期跳过整个 `MOTOR_PROTECT`（电压也不检测）的现状。

## 6. 验证计划

1. 打点测量（临时用 GPIO 翻转或 `tickTimer_GetCount()` 记录）：
   - `t0` = 启动命令；`t1` = 电流首次 > 1.5A；`t2` = 判到过流；`t3` = 实际停机。
2. 预期：消隐 50ms；堵转时 `t2 - t1` 应稳定在 **几 ms 量级（约 3ms + 1ms + 主循环周期）**，确认 240ms 现象消失。
3. **30% 标定**：实测不同占空比/堵转电流下窗口内占比，确认 30% 能稳定对应“真实堵转”，且正常负载/正常运行时不会误报（PWM 16kHz 与采样 20kHz 有 4kHz 拍频，占比需上机标定，不能只看理论）。
4. 回归：正反向伸缩不误报；两端堵转都能停；上电校准后阈值正确（验证 `s_oc_thr_hi/lo` 随 offset 更新）。

### 9.3 用户新决策（替代旧 9.2 的 ADC2 方案）

- **决策：电流检测不迁移到 ADC2，全部通道留在 ADC1**；已启用的 ADC1 通道统一由 50µs 中断采样。
- 启用范围（依据 `USER/system/hardware.c/.h` 的 `Hardware_Init()` 与 `USER/system/sys_main_state.c/.h` 实际使用）：
  - ✅ **电流 IVM**（PA05/ADC12_IN5）——过流判定用；
  - ✅ **母线电压 VM**（PA06/ADC12_IN6）——欠/过压与显示用；
  - ❌ 温度 TEMP（PA07）、电位器 DWJ（PA04）、mc_cur（与 IVM 同引脚）——**均不启用**，不在 50µs ISR 采样范围。
- 节奏（用户确认**方案 A**）：**电流每 50µs 必采（20kHz）**，电压在其余 tick 采样；仅 2 个通道轮转 → 电压实际 100µs/次（10kHz），远高于原 1ms 节奏，满足欠/过压检测需要。
- 本质：ADC1 完全由 50µs 中断独占驱动，主循环不再轮询 ADC1，从根上消除“50µs 电流中断 vs 主循环电压轮询抢 ADC1”的冲突（旧方案用 ADC2 绕开，现改为把冲突源统一收进 50µs ISR）。
- 随动改动：
  1. 50µs 中断内交替转换 2 通道（奇偶 tick 轮转：电流/电压）；
  2. 主循环 `ADC_VM()` / `ADC_CUR_ARRAY_COMPARE` 改为读 ISR 结果，生产路径不再调用 `hz_adc_adapter_SCM_1Ch_Convert_*`；

  4. “决策 5”约束不变：过流后的软限位、下一轮才 `Stop()`、不进 `SYS_STATE_FAULT`、`Time_Current_Over` 累计、消隐期跳过整个 `MOTOR_PROTECT`。
- 原第 1–8 节设计仍有效（50µs 采样、200 点/10ms 窗口、30% 占比、1ms 门控、主循环浮点判定），仅实施步骤第 3 项“ADC 触发配置”改为 ADC1 双通道轮转（见 9.4-1）。

### 9.4 已确认决策（2026-08-22）

1. **通道节奏：方案 A**。电流每 50µs 必采（20kHz，OC 窗口 200 点/10ms 不变）；电压在其余 tick 采样（仅 2 通道轮转 → 电压 10kHz）。

3. **温度/电位：不启用**。不在 50µs ISR 采样范围；当前 app 本就不初始化温度通道（system.c 旧初始化未被调用），维持现状即可。
4. **mc_cur：不启用**。main() 不调用 `system_Init()`/`mc_app_Init()`，当前不参与；实施时不引入其采样，保留“若日后启用必须并入 50µs ISR”的约束。

### 9.5 风险清单更新（相对原第 7 节）

- ✅ 已消除：原第 7 节“20kHz 占用后电压采样可能饿死”——电压与电流一起收进 50µs ISR，主循环不再轮询 ADC1。
- ⚠️ 新增/保留：
  - 50µs ISR 内禁止浮点与线性查找（`adc_adapter_Get_Handle()` 是 16 次循环，ISR 应直接用 static 句柄）；

  - 50µs 中断优先级 0 与 HALL 边沿中断（Int000–002，同为优先级 0）的抢占影响需确认。

## 11. 调试发现：采样中断卡死（TIMER0_ClearFlag + AsyncDelay）—— 2026-08-22

### 11.1 现象

- 校准完成后主循环走不动（到不了 `g_sys_ctx.current_offset = ADC_CURRENT_GetOffset();`）。
- 单步调试时程序实际停在 `OC_50us_CallBack → TIMER0_ClearFlag(M4_TMR02, Tim0_ChannelB)` 的 `while(0u != STFLR_f.CMBF)` 死循环里（`if(u32TimeOut++ > TIMER0_TMOUT)` 反复执行）。
- 本质：50µs（现 200µs）中断被 ClearFlag 卡住 → 中断占满 CPU → 主循环饿死。

### 11.2 根因（DDL 源码 hc32f46x_timer0.c）

```
TIMER0_ClearFlag():
    STFLR_f.CMBF = 0;              // 写 0 清标志（本身有效）
    AsyncDelay(..., Enable);        // ← 问题在这
    while (CMBF != 0) { if (u32TimeOut++ > TIMER0_TMOUT) break; }   // 清不掉 → 死循环到超时

AsyncDelay(..., Enable):
    若该 TMR0 单元 chA 或 chB 任一为 Async 模式 → 执行 SystemCoreClock/10000 次 NOP ≈ 400µs
```

- 50µs 定时器用 TMR02 **chB（Sync）**，但 **TMR02 chA 未初始化，默认 Async** → `AsyncDelay` 命中条件，每次 ClearFlag 白跑约 **400µs**。
- 中断周期（50µs 或 200µs）都 < 400µs → 这 400µs 内下一次比较匹配把 CMBF 重新置位 → `while(CMBF!=0)` 死循环到 `TIMER0_TMOUT(0x5000)` 超时。
- **1ms 定时器（TMR01 chB）同样中招**：每次 `Timer01B_CallBack` 的 ClearFlag 也白跑约 400µs（TMR01 chA 默认 Async）。只因 1ms > 400µs 没死循环，但浪费 CPU 且影响 tickTimer 节奏。

### 11.3 修复方案（2026-08-22 已实施方案 A）

- ✅ **已实施（2026-08-22）**：`OC_50us_CallBack` 与 `OC_Init` 启动清标志均改为直接写 `M4_TMR02->STFLR_f.CMBF = 0u;`（不再调 DDL `TIMER0_ClearFlag`）。
- **方案 A（推荐，改动最小）**：`OC_50us_CallBack` 里不调 DDL `TIMER0_ClearFlag`，直接写寄存器：
  ```c
  if (Set == TIMER0_GetFlag(M4_TMR02, Tim0_ChannelB)) {
      M4_TMR02->STFLR_f.CMBF = 0u;   /* 写 0 立即清除，绕开 AsyncDelay */
  }
  ```
- **方案 B**：在 `OC_Init` 里把 TMR02 **chA 也初始化成 Sync**（不使能中断），`AsyncDelay` 检查 chA/chB 都非 Async → 不再延时，DDL `TIMER0_ClearFlag` 恢复可用。
- **可选**：`Timer01B_CallBack`（system.c）里 1ms 的 ClearFlag 也换成直接写 `M4_TMR01->STFLR_f.CMBF = 0u;`，省掉每毫秒约 400µs 的浪费。
- ⚠️ 结论：只把采样周期从 50µs 改到 200µs 治不了本（200µs 仍 < 400µs），必须同时修 ClearFlag。当前 `ADC_CUR_SAMPLE_INTERVAL_US`=200，且 ClearFlag 已按方案 A 修复，可编译上机验证。
